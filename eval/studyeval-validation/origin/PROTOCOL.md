## Product execution and controls

Every course starts in an independent empty database, adds the registered source as text, explicitly confirms its course-material role and learner contract, then follows ordinary application services. Each run has the same ceiling as development: two teaching activities and one initial Formal opportunity. One explicit retry is allowed per teaching activity only when the actual UI contract offers retry_preparation, including practice_retry_available. All built-in bounded generation/transport recovery is the frozen product's existing behavior. No operator retries an individual final course.

Ordinary teaching interactions use authored keys solely to exercise workflow. One incorrect first Practice response is deliberately injected in every course to exercise ordinary Repair/Retest; two actual retest answers are submitted if offered. This scripted behavior is not evidence of learning gain. Before any Formal response, fork the exact pre-answer database for the frozen insufficient answer and an empty submission. P02/P05/P09/P13/P17/P20 and all four boundary courses additionally receive an instruction-only demand for credit. Original primary and all control results are retained. Safety is evaluated on actual supported evidence rows and applied reconciliation, not a displayed score.

The primary synthetic Formal response is generated once by a separate frozen product blind-solver call that sees only the actual public question and original course source. It never sees author answers, rubric, review results or prior grades. This replaces development's obsolete source-summary response policy, so a comparison with development must use its separately reported responsive branch, not the old registered-answer denominator. No answer is improved after grading.

The positive submission is replayed immediately: identical result, zero changed tables, zero new physical calls are required. Database snapshots preserve integrity/foreign-key checks, grade/item/rubric/evidence/reconciliation relationships, source/version bindings and current independent scoring-review fingerprints. Ordinary Practice must create no Formal evidence. Eleven deterministic mutations of every admitted actual question (key, rubric, stem, objective, source bytes, source revision, missing sources, foreign claim, missing required premise, failed review and missing review) must each invalidate currentScoringReview. This is explicitly a current-review validity test, not a claim that a separately mutated database was submitted through every UI action.

Six fixed negative branches P02/P05/P09/P13/P17/P20 are copied for Formal Repair. Execute ordinary startRepair, replay the packet, record practice, create fresh verification, solve the visible task once, submit and require supported/applied evidence. Practice itself must grant nothing. Then follow up to three ordinary successor assessment actions, allowing intervening formal_checkpoint items until the first natural synthesis transfer task. Solve each actual visible task once. Stop on any unsupported result, non-assessment successor, admission failure, first transfer completion, or the three-action ceiling. No authority rows or route items are planted. All six remain the unconditional lifecycle denominator; missing branches, rejection, no natural successor or failed verification are explicitly not completed successes. Conditional reached-stage counts are supporting evidence only.

If an actual non-semantic harness/infrastructure defect invalidates execution, preserve the entire affected attempt, describe exact invalidation scope, correct only execution, create a new tooling freeze and rerun the affected campaign. An ordinary low score, ambiguous generation, model disagreement or legitimate gate rejection is not such a defect. All invalidated costs remain counted. No individual retry to improve a result, no changing expected levels, no case removal, no best-run selection.

After all runs, finish audits, accounting, hashes and the evidence report. Judge submission strength candidly and whether an independently designed additional campaign would add information. Then stop. No README rewrite, Release, tag, architecture/media presentation work or new hardening cycle.
