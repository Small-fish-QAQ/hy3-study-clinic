# Hy3 Study Clinic — StudyEval evaluation method

## Status

- **Method/specification:** published in this document today.
- **Executable StudyEval harness:** not yet implemented.
- **86-unit corpus:** not yet built or frozen.
- **Final result tables:** not yet produced.
- **Schedule:** implement the harness on 8/31–9/2, build and freeze the corpus on

This is a method specification, not an executed-results report. The absence of a
result artifact is intentional; no future command or experiment is claimed as
available at this commit.

## Runtime model

The future implementation has two commands, kept separate from the current
structural-safety runners:

| Command | Credentials | Responsibility |
| --- | --- | --- |
| `studyeval:offline` | None | Validate the corpus and hash; run deterministic dimensions D2 and D7; run deterministic checks; derive levels **from frozen semantic observations**; run both baselines; generate result tables. |
| `studyeval:hy3` | Explicit Hy3 credentials | The only StudyEval semantic-judge path. Collect atomic observations for open-ended dimensions and freeze them into the corpus. |

After observations are frozen, aggregation is deterministic and offline. “Repeated
evaluation ×3” means repeating observation collection with the credentialed Hy3
command; repeating offline aggregation only tests that the implementation has no
randomness. Every StudyEval run must set `VISUAL_PROVIDER=disabled`. The optional
visual adapter is not part of the evaluation model-call chain.

## Layer A and Layer B

The product’s runtime safeguards (Layer A) and the competition evaluator (Layer B)
answer different questions and are reported separately:

- **Layer A — runtime safeguards (implemented):** schema and ID validation, exact
  quotation/provenance checks, blind support-group verification, criterion gating,
  version/stale fencing, budgets, and deterministic state transitions. Layer A says
  what the application refuses to do; it is not a teaching-quality score.
- **Layer B — StudyEval (planned):** evaluates frozen real-Hy3 artifacts across
  seven educational-quality dimensions. A semantic judge emits observations, never
  a total score; local rules derive each 0/1/2 level.

## Evaluation Case schema and task families

An Evaluation Case is the immutable record:

```text
{
  caseId,
  taskFamily,                 // F1..F6
  frozenInputContext,
  frozenHy3Output,
  qualityTier,                // good | mid | bad | adversarial | system
  constructionAndMutationLog,
  goldLabels,
  targetDimensions,
  corpusHash
}
```

The six task families correspond to real Hy3 operations: **F1 Curriculum proposal,
F2 Teaching Brief explanation, F3 Practice authoring, F4 short-answer semantic
grading, F5 evidence relation/support-group proposal, and F6 Repair proposal**.
Each case stores the exact input context and output bytes used for judging. Gold
labels are written beside the case and are never generated by the judge.

## Seven dimensions and written anchors

Every applicable case receives one of three written levels. There is no unanchored
1–5 scale.

| ID | Dimension and outputs | Scorer | 2 — pass anchor | 1 — partial anchor | 0 — fail anchor |
| --- | --- | --- | --- | --- | --- |
| D1 | Source-fact fidelity (F1/F2/F4/F5) | Deterministic checks plus structured semantic observation | Every source-specific assertion has an exact verifiable span and does not contradict accepted material. | At least one assertion cannot be verified, but no assertion contradicts the material. | At least one assertion contradicts the material or contains a fabricated citation. |
| D2 | Evidence-binding correctness (F5 and cited F2) | Purely deterministic | A currently bound support group fully supports the proposition. | A supporting combination exists in the material, but the current binding is wrong (mis-binding). | No supporting combination exists, or bound evidence contradicts the proposition. |
| D3 | Objective and scope fidelity (F1/F2/F3) | Deterministic scope checks plus structured semantic observation | Output stays within accepted scope and construct depth; general extensions are explicitly labelled. | Output stays in scope but depth is mismatched, or a general extension is not labelled. | Output leaves accepted scope or presents a general extension as a material fact. |
| D4 | Pedagogical soundness and clarity (F2/F6) | Structured semantic observation plus human label | No material error or key reasoning jump; examples serve the objective; key terms are defined before use. | Conclusion is usable but includes at least one reasoning jump or one undefined key term. | A material teaching error, circular explanation, or unusable intervention is present. |
| D5 | Assessment defensibility (F3/F4) | Deterministic checks plus structured semantic observation | Premise is visible, answer is not leaked, criteria are source-defensible, and grading agrees with its evidence. | The item is answerable but has an unbound criterion point or local ambiguity. | The item is unanswerable, leaks the answer, is trivial restatement, or conflicts with its evidence. |
| D6 | Diagnostic specificity and repair usefulness (F6) | Deterministic seeded-defect checks plus structured semantic observation | Diagnosis identifies the actual gap and prescribes a concrete, executable repair action. | Diagnosis is in the right domain but only restates the topic generically. | Diagnosis targets the wrong gap or the proposed repair cannot be executed. |
| D7 | False-mastery resistance (system replay) | Purely deterministic | A changed representation, delay, or transfer failure prevents persistent mastery. | Mastery remains but the state is marked as a risk. | Familiar phrasing alone produces a persistent mastery claim. |

D2 and D7 intentionally use no model. The former tests evidence identity and set
operations; the latter replays the real state machine.

## Anti-circularity controls

Six controls prevent “Hy3 judges its own prose” from becoming the result:

1. The semantic judge emits atomic observations `{defectType, location, evidenceRef}`
   and never emits a score; local rules derive levels.
2. The judge is blind to the quality tier, mutation log, generator rationale, and
   any gold label.
3. The judge uses a separate prompt identity and schema version from every generator.
4. Length-only and deterministic-only baseline scorers run on the same frozen cases.
5. Human labels calibrate and audit the judge; the judge never self-validates.
6. D2 and D7 are model-free, so their central claims cannot be caused by judge
   preference.

## Corpus and sample plan

| Group | Count | Construction |
| --- | ---: | --- |
| Good/mid/bad triplets | 54 (18×3) | Good is a real Hy3 output that passed application gates; mid/bad are deterministic mutations with a retained mutation log. |
| Natural bad samples | ≥6 | Real Hy3 failures recorded privately, labelled as natural rather than mutated. |
| Adversarial samples | 20 | Four each of padding, jargon stacking, fabricated citation, correct conclusion with wrong binding, and familiar-phrasing false mastery. |
| D7 system scenarios | 12 | Replayed paraphrase, delay, transfer, and near-neighbour-confusion states. |
| **Total** | **86** | Negative/adversarial/system cases are 38/86 ≈ 44%. |
| Human-labelled subset | 30 | Stratified across task families and quality tiers, with one annotator. |
| Repeated observation collection | 30×3 | Three independent Hy3 observation rounds; aggregation remains offline. |

The corpus uses four real course documents (two Chinese and two English/bilingual)
plus the repository’s five existing fixtures and at least two subject domains.
The frozen corpus hash and each construction/mutation log are part of the tracked
case data. Raw credentials, local paths, learner text not required by a case, and
raw provider transcripts are never tracked.

## Scoring and validity protocols

### Discrimination

- Strict triplet ordering accuracy: the proportion of 18 triplets for which
  `good > mid > bad` holds. A strict criterion avoids hiding a collapsed ordering.
- Pairwise ordering accuracy over the 54 good/mid and mid/bad comparisons.
- Per-dimension **Kendall tau-b** between gold tier and derived ordinal level. Tau-b
  is appropriate because three-level data create ties; a three-point Spearman
  coefficient would mis-handle those ties.
- A 3×3 confusion matrix and a reason-coded record for every ordering failure.

### Consistency

- For each dimension, report exact agreement and adjacent agreement (±1) against
  the 30 human labels.
- Re-label 20 cases after at least 24 hours and report the annotator’s **intra-rater**
  agreement. There is only one annotator, so inter-annotator agreement is
  mathematically unavailable and will not be implied.
- Across three independent Hy3 observation collections, report modal-level stability
  and decision-flip rate.
- Report an applicable sample size `n` separately for every dimension. A case only
  contributes to its target dimension; F5 cases do not silently become D4 cases.
  D7 has at most the 12 system scenarios (8 if the documented schedule reduction is
  used), and D2/D7 consistency is reported separately from semantic-judge agreement.
- Compute quadratic weighted kappa (QWK) only when a dimension has an applicable
  label structure and defensible `n`; publish the coefficient together with `n`.
  For a dimension with too few applicable cases, report exact/adjacent agreement and
  explicitly state that `n` is insufficient for a kappa statistic.

### Adversarial robustness

- **False-pass rate:** the fraction of adversarial cases whose target dimension is
  not at its prescribed low level. The threshold is frozen before running.
- **Inflation amplitude:** the level difference from the clean control for the same
  case.
- **Length confound:** Kendall tau-b between token length and total derived level on
  clean samples; a near-zero value is the desired direction because length is not
  the construct.

### Baselines and result separation

1. **Length-only baseline:** maps token-length bands to the same 0/1/2 output space.
2. **Deterministic-only baseline:** uses only local checks available without semantic
   observations.

The final report keeps two tables separate: application quality (real-Hy3 good-arm
level distributions and reason-coded failures) versus evaluator validity (ordering,
Kendall tau-b, human agreement/QWK where applicable, intra-rater agreement, repeated
stability, adversarial false-pass, length confound, and both baselines). An application
result is not evidence that the evaluator is valid, and evaluator validity is not a
claim that the application improves learning outcomes.

## Prior methodology and scope boundary

The private v0 evaluator and its 16/16 ordering figure are prior methodology work on
fixture data, not a StudyEval result. The final public method does not reuse v0’s
“Evidence Integrity” or “Workflow Reliability” as application-quality dimensions;
those remain Layer A safeguard checks. No future multi-model comparison is assumed.
