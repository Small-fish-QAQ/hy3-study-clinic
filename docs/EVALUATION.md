# StudyEval：开放式教学质量的评估协议

## 当前状态

**这是公开评估协议与当前状态，不是最终实验结果。** Final Fresh Evaluation（最终新样本产品评估）、真实人工标注与人工一致性验证尚未完成。当前仓库没有可作为最终验证依据的 StudyEval 执行器、冻结语料和结果包；不声明评估方法已经通过最终有效性验证。

现有 `eval:fake` 和 `eval:hy3` 是可执行的结构与接口检查。它们不实现下面的教学质量协议。协议不提供尚未存在的 npm 命令，不将开发调试、历史样本复测或模型代填标签视为最终独立验证。

截至 2026-09-12，私有评估器固定为 `studyeval-v1.5-micro-closure`（SHA-256：`e088e986a5c968febcaf51f99511258fd452759b935fd454327f61dcaa38dfdb`），评估器开发已永久关闭。已完成的小型新样本检查结论为 **SMALL FRESH CHECKPOINT FAIL**：16 个新构造案例、3 个来源家族，共请求 32 个维度判断，得到 20 个数值判断与 12 个 U，无无效观察。

检查区分了清晰的化学教学强／有限／差对照，并检出了错误答案、误授学分、实际解答泄露和错误补救；未发现可确信为错误的最终数值判断。但合格教学、正确评分和独立测评的正对照过多保留为 U，未达到预先规定的证据充分性要求。这是评估器可用性与正对照覆盖不足的发现，不能只用 20 个数值判断作分母报告准确率，也不能据此推断产品总体质量。

检查语料、输出及全部衍生材料保持私有，并永久排除于 Final Fresh Evaluation 的未见证据之外。该检查不是最终产品基准；正式评估数据集、运行脚本、完整结果表与基准结论由后续 Final Fresh Evaluation 提供。

## 分开回答三个问题

| 问题                     | 所需证据                                                               |
| ------------------------ | ---------------------------------------------------------------------- |
| 应用是否按规则运行？     | 来源校验、状态机、版本与重复提交检查、失败恢复；见测试和 `eval:fake`。 |
| Hy3 产生的教学是否可用？ | 冻结的真实输入与输出、适用维度、逐条依据、自然失败及人工复核。         |
| 评估器的判断是否可信？   | 独立参考、受控对照、重复测量、人工一致性、对抗样本与失败分母。         |

结构合法不代表讲解正确。应用得分高不代表评估器有效，两者也都不能证明学习效果提升。

## 评估单元与证据

评估单元可以是课程提案、讲解片段、题目、一次评分或一次补救。每个单元需要保存：匿名案例 ID、产品提交和生成配置、资料及目标、学习者实际可见的上下文、原始输出、评分标准与实际作答（适用时）、发生在题目前的真实教学暴露、构造方式和内容哈希。

参考标签与缺陷构造记录单独保存，评估模型不可见。对题目的独立求解要隐藏作者答案，同时保留作答所必需的情境和前提。当前题目文本或评估包里存在参考答案，不等于学习者之前已经见过解答。

开发样本与最终新样本分开，最终运行前固定产品版本、方法、样本清单和报告规则。未生成、目标遗漏、正式资格被拒绝、超时和无效输出都保留，不从分母中悄悄移除。

## 六个操作维度

以下锚点用于约束待验证的判断规则。每项只评价适用的材料；不把不同任务硬合成一个总分。

| 维度           | 2：满足                                                                | 1：局部缺陷                                      | 0：实质失败                                                        |
| -------------- | ---------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------ |
| **事实与来源** | 核心事实、条件和计算与可检查依据一致；资料归因可核对。                 | 有局部不准确或不完整归因，尚未破坏主要结论。     | 核心事实、机制、计算或引用错误，足以改变结论。                     |
| **目标与范围** | 覆盖应完成的目标，保持所需能力与深度，扩展内容有边界。                 | 保留目标但覆盖或深度有局部不足。                 | 丢失关键目标、把应用降为复述，或用范围外内容替代。                 |
| **教学解释**   | 关键推理、例子和边界足以帮助理解当前目标。                             | 主要结论可用，但有明确的推理跳步或说明缺口。     | 错误机制、循环解释或关键缺失导致教学不可用。                       |
| **题目质量**   | 学习者可见前提足够，当前答案成立，任务有意义且无实际泄题。             | 局部歧义或较弱任务仍允许可辩护作答。             | 不可答、错误答案、缺少决定性条件或先前直接暴露了解答。             |
| **评分判定**   | 接受有依据的等价正确回答，拒绝缺少必需要点的回答，分数与证据后果一致。 | 核心判定成立，但局部反馈或非关键评分理由欠准确。 | 错拒等价正确回答、误授不足回答正式证据，或评分后果与必需标准冲突。 |
| **诊断与补救** | 针对实际错误提出有依据的假设、解释和可执行的后续检验。                 | 方向相关但缺乏定位或具体后续动作。               | 诊断错误、补救与实际缺口无关或不可执行。                           |

此外保留 **U（依据不足，需要复核）**、**无效输出（执行或格式失败）**和**不适用**。U 不能算作自动判对，无效输出不能当成低分样本以隐藏评估器失败。只有复核者检查确切材料后，才能另行记录人工结论；原判断保持可追溯。

尤其要区分：正确拒绝一个不足回答属于好的评分判定；补救提案可按内容与可执行性评价，不需要假装学习者已经完成补救；局部解释不能被要求覆盖资料中的所有目标。

## 语义判断与本地计算

模型提供有位置和原文依据的结构化观察。本地规则验证字段、证据身份、适用维度及判断约束，再推导等级和汇总。自动规则不能代替语义真值：引用存在不证明支持充分，执行算术不证明前提正确，多个 Hy3 判断一致也不是外部独立真值。

证据绑定与正式进度另做系统检查：在控制语义前提的条件下，更换引用绑定、输入近似但不足的回答、重放提交或引入延迟和新表现，检查实际证据与进度变化。此类受控结果只支持对应条件下的系统结论，不能被称为真实学习者的误授学分率或长期掌握效果。

## 如何检验评估器

| 检验         | 设计与报告要求                                                                                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 判别力       | 比较有独立参考的较好、局部缺陷和实质缺陷输出；记录修改了什么，报告严格顺序、成对判断及每维混淆情况。通过应用门控不自动成为“好样本”。                             |
| 人工一致性   | 人工检查确切资料、可见题目、作答和后果；标签先独立完成再处理分歧。报告每维适用 `n`、精确一致率，样本条件允许时再给加权 kappa。单个标注者不能提供标注者间一致性。 |
| 重复稳定性   | 对同一冻结输入重新收集独立模型判断，报告包括 U 和无效输出的转变；重新计算同一份缓存结果只证明离线计算稳定。                                                      |
| 对抗性       | 检查冗长填充、术语堆砌、伪造引用、正确结论配错证据、评分指令注入，以及真实的先前答案暴露能否蒙混过关。                                                           |
| 基线与可用率 | 在同一批样本比较长度基线、确定性检查与语义方法；同时报告请求数、可用判断数、拒答、无效数和条件分母。                                                             |

人工或模型审阅者都需要区分正确的等价推理与逐字答案匹配，对未确立的适用条件保留不确定性。问题难度、措辞好听或输出长度不能代替事实和能力检查。

## 最终报告需要补齐什么

后续结果包应包含可公开的样本及权利说明、冻结的方法和版本、运行入口、输入输出身份、失败与排除记录、参考标签来源、每维分母和完整结果。模型判断采集需要显式 Hy3 配置，并关闭可选视觉路径；冻结后的核验与汇总应可无密钥重放。

应用表现、评估器有效性、运行成本分开呈现。自然目标从保留、教学交付、正式准入、作答、证据到进度的损失都应可见。新样本结果、人工一致性和长期学习效果在有相应证据之前均不作结论；没有在本次仓库整理中启动这些实验。
