# Hy3 Study Clinic · 实战任务 1 参赛说明

**从学习资料出发，把讲解、练习、补救与正式验证组织成可以持续执行的课程。**

本项目为「腾讯犀牛鸟开源人才培养计划 · 混元大语言模型项目」个人活动作品，不代表腾讯或 Hy3 官方发布。本文描述当前提交中的产品；评估结果的公开边界以[验证说明](VERIFICATION.md)为准。

[观看演示](DEMO.md) · [运行项目](SETUP.md) · [评估协议](EVALUATION.md)

## 场景与用户价值

学生和自学开发者常有一份明确的资料，却没有一条可持续执行的学习路线。模型可以解释概念，但学习者仍要自己挑选顺序、设计练习、判断错误、安排复习，并区分“刚刚看懂”与“能够独立使用”。

Study Clinic 以课程作为持续保存的工作单元。资料决定学习范围，学习者选择全局深度与重点；课程结构经确认后派生计划。每次进入课程，界面提供下一项学习任务，错误可以接着进入补救和复测，正式证据可以回看。

预期价值是降低组织学习和追踪薄弱点的负担。**该价值是产品设计目标；目前没有学习效果实验，不能将它写成已经测得的成绩或保持率提升。**

## 一段完整的使用过程

以学习一份技术资料为例，学习者先上传文本，选择“熟练运用”，并指定资料内希望多练习的主题。Hy3 提出课程单元、目标与先修顺序。学习者可改名称、在约束内调整顺序、切换重点，然后接受课程结构。

系统据此派生学习计划。讲解用连续段落和案例建立理解，在关键步骤要求学习者判断；答错时提供有限提示与脚手架。选中不理解的内容可以向旁边的 Tutor 提问。理解检查、提示和聊天均不产生正式证据。

进入独立练习后，如果回答错误，Hy3 根据这道题、实际选项、已展示教学和学习者补充的思路提出诊断与补救。学习者阅读解释和例子，再回答新的复测问题。通过只完成当前非正式练习任务。

对于有足够来源和评分依据的目标，正式测评保留题目版本、评分标准、作答和判定。只有通过本地证据门控，结果才进入正式进度。未通过则安排补救与新的验证。深入迁移课程为有正式资格的目标增加构造新场景、应用原则、改变条件并解释差异的任务。

课程主页和进度页汇总当前任务、正式证据、待补救内容与到期复习。知识地图用于概念导航，学习者也可暂停、继续或进行允许的临时探究。

## Hy3 如何参与

本项目的开放性来自教学过程：课程划分、讲法、题目、学生措辞和补救方案都没有唯一标准答案。Hy3 参与的不只是最后一段回复。

| 任务           | Hy3 产生的内容                   | 接受条件与最终权威                                                   |
| -------------- | -------------------------------- | -------------------------------------------------------------------- |
| 资料理解与建课 | 概念、课程单元、目标与关系提案   | 本地检查来源和结构；学习者接受课程结构；普通计划由本地编译。         |
| 教学与练习     | 解释、案例、引导问题、练习与反馈 | 检查当前目标、来源、结构、明显泄题与重复；内容审阅仍可能出错。       |
| 上下文辅导     | 针对已展示内容的解释与追问回复   | 来源由服务端解析保存；不暴露未来复测答案，不推进正式进度。           |
| 语义判定       | 证据关系、评分要点是否满足       | 本地代码计算绑定和分数，判定正式证据资格；语义判断不被当作数学证明。 |
| 诊断与补救     | 对实际错误的解释、补救内容和复测 | 绑定当前目标与错误记录，校验后保存；诊断是待后续表现验证的假设。     |

真实模式使用 Hy3 的兼容接口；参赛配置关闭可选视觉描述适配器。Fake 模式用于安装后的流程体验与确定性回归检查，不能支持模型质量结论。

## 三个核心设计选择

**学习路线和记录持续存在。** 已确认课程结构、派生计划、当前任务、教学内容与作答分别保存。中断恢复、显式重试和版本检查把一次次模型请求连接成学习过程。

**资料与补充教学有可见边界。** 引用保留资料修订、文本位置及适用的页码、章节或幻灯片信息。Hy3 可以解释和举例，但生成的解释不能因为附了一条引用就自行成为评分依据。引用位置正确与语义支持充分是两件需要分别检查的事。

**教学完成与正式证据分开。** 提示、聊天和练习可以帮助学习，却不能自行授予正式进度。正式证据还受目标、构念、来源、评分标准、作答和版本约束；长期掌握要求额外的多样表现与延迟证据。更深的学习设置不会扩大资料本身可支持的判断。

这些边界提供可检查的依据，也会造成保守拒绝：资料不足或目标暂时无法获得正式资格时，系统可能只能教学，不能验证。当前并不声称全面解决了虚假掌握。

## 评估设计与当前证据

实战任务的第二部分是设计可操作的开放式评判标准。StudyEval 协议分别评价事实与来源、目标范围、教学解释、题目、评分判定和诊断补救，保留无法判定与评估器失败。评估器自身还需要判别力、人工一致性、重复稳定性和对抗性验证。

**本检查点不发布最终 StudyEval 得分，也不声称最终新样本评估、新人工标注或人工一致性实验已经完成。** 公开协议见 [EVALUATION.md](EVALUATION.md)。开发调试结果不能替代冻结方法后对新样本的验证。

当前可公开复核的证据包括代码与测试、离线结构检查，以及 [2026-07-31 的真实 Hy3 记录](evidence/hy3-online-verification.md)。该记录在明确的旧提交上完成 6 项小样本操作，不代表当前完整课程流程的成功率。演示展示交互与界面，不作为正式评估样本。
