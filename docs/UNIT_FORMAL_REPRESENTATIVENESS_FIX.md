# 单元 Formal 代表性根因与定向修复

2026-10-13。已完成源码、真实课程记录、隔离库与本地 HTTP Mock 验证；本轮 **0 次真实付费请求**。这不是新一轮 MoMA 教学质量验收，固定离线候选及模拟满分不能证明真实模型的出题质量。

## 查明的根因

沿知识、确认 Map、单元投影、代表选择、作者、准入、评分、Evidence 追踪，问题在出题之前已经存在，不是评分把未测内容误认成掌握：

1. 真实 Map 的 `cell_2` 只关联“按步骤构造真值表”和“自然语言形式化”两个目标。Lesson03 的“三变元、多前提真值表判断”目标既不在这个 cell 的 `objectiveIds` 中，也不在 domain 的 `coreObjectiveIds` 中。综合课程卷可以有较粗取样，但直接用它裁剪单元卷会丢掉该单元的主要教学目标。
2. `set_2` 把例题1和例题2的六个知识放在一个 OR 集合中。本卷只选方法知识和集合中的一个代表。真实原始选择是“方法 + 例题1的推理命题”；`answer=[]` 结构拒绝后，替换为“方法 + 例题1的自然语言形式化”，仍全部来自第一课。并不是先考了第二课又被评分丢掉。
3. 原 `make(batch)` 只向作者提供所选两个知识及其来源；两个 Lesson 虽进入 `teachingIntent`，蓝图和实际题源依然未要求第三个目标。`checkPaperCoverage` 只检查 cell、mandatory 和“任一代表”；既没有目标语义的核查合同，也没有单元整体取样检查。题目于是合法地就绪。
4. `QuestionAdmission`、服务端逐 criterion 评分与 Evidence 如实记录了那两个实测知识。本轮未修改其历史成绩，也未扩大旧成绩的证明范围。

运行证据：[旧蓝图与选择轨迹](../output/unit-formal-quality/trace-before.json)、[前后对照及 HTTP 结果](../output/unit-formal-quality/comparison.json)。原题、rubric、模拟回答和原评分仍在 [真实内容附录](real-course-evaluation/ACTUAL_TEACHING_CONTENT.md)。

这不是单个模型偶发选题差：实际七个单元中，旧投影遗漏目标的单元有五个。按单元顺序，旧目标数量为 **1 / 2 / 3 / 2 / 2 / 5 / 4**，已确认的教材教学目标为 **2 / 3 / 4 / 3 / 2 / 5 / 5**。其余单元的模型新题本轮没有生成，这个比较只证明范围缺口。

## 修复后的行为

单元蓝图由**已确认的本单元教材教学目标**在本地编译，不再把综合课程卷的抽样决定当成完整单元目标。保留原 cell 的 mandatory、权重、难度及代表规则；将被同一课程池遗漏的目标并入有相应知识支撑的 cell。若综合卷完全未给这些目标分配题源，从确认目标编译一个合并的本地能力范围，仍不逐知识点造题。该补充范围的难度沿用学习深度，权重取现有单元 cell 的均值（没有原 cell 时为1）；最终仍由现有服务端归一化评分。这是确定性的补充规则，不声称它是教师重新标定的量表。

`objectiveRequirements` 冻结完整目标文本、知识关联和认知要求。每个目标要么已有必考知识支持，要么有属于该目标的代表池；大池内的不同目标不再互相替代。重叠代表池优先复用已选成员，局部替换也先轮换窄池后复用，避免无意义地扩大样本。一个代表可以支持多个目标，但这些目标必须分别由实际任务支持。

作者得到相关目标的完整背景知识与来源，同时明确哪些知识是本卷选定的代表。背景知识不自动变成考试任务或 Evidence。多个目标可以在同一道综合题或明确子问中自然考查；本轮没有最少题数、覆盖百分比、每知识点必考或每题必须反例的要求。

原题作者另有“每slot估计1600可见token”的假设。新单元的一个cell可能承接多个目标，因此其软输出估算现在计入目标数和所选知识/来源字段，不再按slot数截短综合题预算。模型输出cap、输入与输出共用的context限制及预算预检保持生效；这不是放宽模型配置或增加业务硬上限。

现有盲解增加 `expectedObjectives` → `assessedObjectiveIds`；现有 coverage 增加实际 `objectiveIds`。**知识 ID 相交、目标标签相同、题面提及均不构成目标覆盖。** 主观题还需要已有 rubric 核查把目标对应到题意要求的必需评分点。新卷缺目标、认知动作不够、盲解不支持或缺选定代表时不能就绪，只沿用原 slot 的一次局部替换。没有新 Review Agent、蓝图模型请求或默认审核轮次。

综合课程卷仍使用确认时的原课程蓝图；本轮没有将所有单元目标强加给综合卷。Lesson、Tutor、Practice、CSS、数据库 Schema和模型设置没有重构。

## 前后实例与验证

| 实例 | 修复前 | 修复后已验证结果 |
| --- | --- | --- |
| 真实“真值表法”，2课7K | 1 cell、2目标；1题3小问，仅例题1相关的2K | 新蓝图仍1 cell，承接3目标；HTTP固定候选仍1道综合题，要求两变元形式化/四行表和三变元多前提/八行表，独立合同核查确认3K，Evidence仅写这3K，其余不从总分广播 |
| 跨课大 OR 池 | 选一课即可满足集合，另一独立目标可以消失 | 目标内部可任选，目标之间不能互相替代；三个目标仍合并在原1 cell |
| 综合卷背景内容、混合必考/选考、跨单元 cell | 背景目标缺 cell；有必考 cell 时其他单元目标可能未进入 required | 按本单元确认目标补范围；外单元 mandatory 裁掉后不遗漏本单元目标；纯拓展目标不自动变为必考教材 |
| 同一 K 对应“解释”和“错误诊断” | 知识覆盖与高等级标签可能掩盖未考诊断 | 盲解不支持诊断时，即使作者贴了 ID 与高等级标签也拒绝，卷保留 draft，不发成绩/Evidence |
| 300K、5个核心领域 | 课程卷抽10K | 综合卷、单元卷均仍抽10K；重考轮换，未测K保留，不逐300K考试 |
| 原单元冻卷/成绩 | 原来已成立的2K证据 | 同 paperRequestId直接返回原冻结试卷，0模型请求；原payload字节保持。新请求才使用新规则；冲突单元仍拒绝 |

真实课程验证用只读备份创建 `output/unit-formal-quality/validation-*.sqlite`，生产 API → Runner → `HttpCourseProvider` → 本地 HTTP → 准入/评分/持久化，外部地址由测试 fetch 强制拒绝。四个请求是作者、盲解、rubric、主观评分，没有额外模型服务。固定候选的真值表由完整二/三变元枚举生成，并人工核对前提全真行。模型回答、评分和新颖性是**测试夹具**，不是 MoMA 响应或真人学习效果。

原冻卷没有新增目标字段，不能直接按新字段判定其旧成绩失效。对照文件中 `gapsUnderNewPolicy` 是将未修改旧payload放到新合同下的结构检查，包含字段未存在导致的目标缺口；真实遗漏结论另由旧蓝图、题面和取样轨迹证明。正式路径不会对旧卷作这次重解释。

测试与日志均在 `output/unit-formal-quality/`：全量 **290项测试通过（shared20 / server225 / web45）**，shared/server/web生产构建、eslint/prettier、`scripts/eval-clinic-offline.mjs`、`scripts/verify-course-http.mjs` 及真实 Map 的本地 HTTP 对照均通过。新增四个目标取样回归和一个目标预算/cap回归，保留原300K综合卷回归并增加单元卷同样例。

## 修改位置与数据保护

本轮产品源码集中在：

- `apps/server/src/services/unitAssessment.ts`：本地单元目标编译、代表池和范围。
- `apps/server/src/services/courseQuestions.ts`：目标/选定代表检查、完整目标背景、代表复用及冻结请求恢复。
- `apps/server/src/services/questionAdmission.ts`：目标独立支持、认知要求与必需criterion绑定。
- `packages/shared/src/domain/course.ts`、`apps/server/src/llm/courseContract.ts`、`coursePrompts.ts`：两个可选持久化字段及现有模型调用合同。
- `apps/server/src/llm/courseProvider.ts`、`courseProvider.test.ts`：新单元的输出估算按实际目标/来源结构计算，仍受原物理cap约束。
- `courseFakeProvider.ts`：离线夹具适配；不能用其按知识关联填目标的简化模拟证明真实语义能力。
- `unitAssessment.test.ts`（新增）、`clinicFormal.test.ts`、`clinicRepresentative.test.ts`：根因、恢复和大范围抽样回归。

没有数据库迁移、旧卷重写、旧成绩重算、源码快照恢复/删除、commit/push。全部3,142个快照文件、受保护数据库main/WAL文件与所有既有数据库表记录、原模型配置/key以及Git HEAD核对保持不变；见 [保护检查](../output/unit-formal-quality/protection-after.json)。本地 Mock 服务均随脚本正常关闭，已有用户服务保留。

## 成本、恢复和最小 MoMA 复测

正常调用次数保持“作者 + 客观盲解”，或“作者 + 主观盲解 + rubric”，主观交卷再评分。目标更多时题面、背景和核查的 token/耗时可能增加；不承诺同样的真实账单金额。若能力无法合理合并，题目内容需由实际要求决定，本地 cell 不代表任意固定题数指标。没有额外规划/全量审核费用，也没有绕过预算保护。

内容失败仍最多局部替换一次；技术失败保留候选、代表、已准入题、蓝图和已判分项，只恢复缺项。现有显式补题与重考规则保留。新增目标不改变同一次恢复的冻结范围；旧 draft也沿用其原合同，需要新规则时另开新卷。

建议用户授权后的最小真实复测是：在已有真实课程或隔离副本中新开一次“真值表法”单元 Formal，**无需重新导入、准备课程或生成 Lesson**；逐一核对三目标、两课关键条件、实际公开任务、盲解/rubric与实际被测K，然后提交一份完整作答检查评分/Evidence。若为一道主观综合题且无失败，通常4个模型请求；真实题型和局部失败会改变数量。旧100%成绩保持原2K证明范围。还可故意遗漏三变元表验证对应criterion不满足，但这是下一步可选评分测试，本轮没有授权执行。

待真实验证的是模型能否稳定生成代表性充分且可解的新卷，以及目标语义识别、难度和rubric是否合理。真实取样不要求复刻离线候选或恰好3K。Tutor个别推理错误、Lesson自然语言过度确定、历史CP rubric偏窄未发现与本次投影/取样有明确共同根因，继续保留为已知案例，没有逐条新增审核或特殊数学规则。
