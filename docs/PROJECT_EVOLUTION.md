# Hy3 Study Clinic — Project Evolution

This is a concise chronology, not a second product specification. The authoritative design for the next implementation is [STUDY_CLINIC_AGENT_PRODUCT_DESIGN.md](STUDY_CLINIC_AGENT_PRODUCT_DESIGN.md).

## Stage 1 — Rhino-bird Issue #4 awarded submission

Hy3 Study Clinic began as the awarded Tencent-Hunyuan/Hy3 Issue #4 submission: an evidence-grounded learning loop from source material to Concepts, a personal knowledge Graph, assessment, deterministic grading, mistakes, remediation, and persistent mastery.

Historical checkpoint: immutable tag issue-4-final.

## Stage 2 — post-award reliability, extraction, teaching, and evaluation

The product then strengthened activity launchability, atomic and stale-safe grading, section-aware additive extraction, honest structural mapping, lesson-card provenance, fake-provider parity, and evaluation coverage. The system became substantially more reliable without changing its core graph-led shape.

Historical checkpoint: immutable tag pre-dogfood-complete.

## Stage 3 — real dogfood exposed the orchestration gap

Real study use showed that a graph-led collection of reliable learning tools still required the learner to orchestrate the journey: reconstruct the course, decide what was next and why, maintain time and completion rules, remember what had actually been verified, schedule synthesis and review, and recover when the route drifted.

The remaining problem was not another disconnected AI feature. It was durable course execution.

## Stage 4 — mixed-initiative Learning Execution Agent

The current design direction is a user-governed, evidence-gated, auditable Learning Execution Agent. It adds a learner-confirmed Learning Contract, learner-visible Curriculum, accepted versioned StudyPlan, flexible SessionAgenda, conversational StudySession, formal progression, Coverage/Risk Ledger, and adversarial readiness while preserving the existing grounding, grading, state, and history guarantees.

Old audits, syntheses, and implementation plans remain available through Git history and the historical tags. They are not copied into a docs/archive directory because Git is the archive.
